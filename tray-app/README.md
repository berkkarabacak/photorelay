# tray-app/ — PhotoRelay for Windows

The app your family actually sees. Electron shell around the proven
`relay/` receiver engine. Zero command line, giant text, one job per screen
(docs/ux-design.md §0).

## What you see

| Screen | When | What it says |
| --- | --- | --- |
| **Pairing** | First launch | "Point your phone's camera at this picture" + a big QR code. After the phone connects: 6 words to compare with the phone's screen (SAS). |
| **Ready** | Phone paired | "Open PhotoRelay on your phone and tap 'Copy all my photos'. That's it." |
| **Transferring** | Copying | Giant progress bar, "N of M photos". Closing the window keeps it working in the tray. |
| **Waiting** | Connection dropped | "Connection lost — waiting for phone… Nothing is lost. It will continue by itself." |
| **Done** | Verified | "All done! N photos and videos are safe on this computer." |

## Run it (dev machine)

```bash
npm install
npm run build
npm start          # or: npm run smoke  (renders, screenshots to smoke.png, quits)
```

The photo library defaults to `Pictures\PhotoRelay` (override with
`PHOTORELAY_LIBRARY`).

## Architecture

```
src/main/host.ts   ← pure Node: pairing state machine, progress, copy deck
src/main/main.ts   ← Electron glue: window, tray icon, IPC
preload.cjs        ← contextBridge (getState / onState)
src/renderer/      ← React UI (Vite), one screen per phase
tests/             ← e2e: QR pairing → SAS → transfer → done (no display needed)
```

The receiver from `relay/` runs in the Electron main process (Electron's
bundled Node 24 provides `node:sqlite`). The main process is bundled with
esbuild (`scripts/build-main.mjs`); the tray icon is generated by
`scripts/make-icons.mjs`.

Until the Android/iOS apps exist, the reference sender CLI plays the phone:
it accepts the QR payload directly via `--pair-uri`.
